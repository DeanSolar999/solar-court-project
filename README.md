# Solar Court Project｜曜日羽球場地募集

曜日羽球團 Solar Badminton 的 2027 年場地募集活動網站。

GitHub Pages 網址：<https://deansolar999.github.io/solar-court-project/>

## 目前功能

- 活動公告、抽獎獎品、球團福利、場地與個資告知。
- MIZUNO FORTIUS 11 POWER 頭獎圖片與可展開規格。
- 手機與桌機排版。
- Google 託管表單登記入口與填寫前說明；目前入口關閉。

**正式登記準備中，尚未開放收件。** 此版本為收件準備中的活動公告頁。GitHub Pages 只提供活動公告與登記入口，已移除所有個資輸入欄位，也沒有報名 API。正式填寫、驗證與儲存由獨立的 Google 託管表單承接。發布公告網站不等於開放收件。

## 開放條件

設定集中在 `src/lib/registration-config.ts`。目前 `open: false`、`formUrl: ''`、`formUrlVerified: false`、`publicNoticeApproved: false`、`startsAt: null`，因此所有正式登記 CTA 都停用。

須先取得本次完整公告的核可並完成 Google 託管表單驗收，再設定明確的開始時間、已驗收的正式 `/exec` 網址及開放狀態。`publicNoticeApproved` 只代表目前公開告知版本獲核可，不表示仍待公告的獎品價值或稅務細節已確定。開始時間需含時區，例如 ISO 8601 的 `+08:00`；目前未指定日期。場地協助登記截止為 2027 年 12 月 31 日 23:59:59（台北時間），自 2028 年 1 月 1 日 00:00:00 起停止導向登記；此期限不是首波抽獎資格截止。

- 所有開放條件必須同時成立；單改 `open` 不會產生可用連結。
- 網址只接受 `https://script.google.com/macros/s/<deploymentId>/exec`；不接受 query、hash、帳密、其他網域或 `/dev`，不能放參加者個資或共用密鑰。
- URL 格式檢查不等於部署驗收；更換網址後必須重新驗收並更新 `formUrlVerified`。
- 開放前同步檢查 `index.html` 的 title、description、OG、Twitter 與 noscript 文字，以及 Google 表單的實際開始／截止設定與完整活動辦法。
- 本版告知版本為 `2027-v14-2026-10-12`，須與 Google 託管表單、後端保存的同意快照一致。
- GitHub 頁面的時間檢查只是入口提示；Google 表單後端必須獨立依伺服器時間、收件開關與完整驗證拒收未開放或逾期資料。

仍待確認：各獎品實際價值、付款與扣繳資料，以及回覆 14 日、領取 30 日的明確起算點。現在只能保留「依得獎通知於 14 日內回覆、30 日內領取」的表述，不推算固定曆日，也不改成「回覆後 30 日」。未自行設定付款／扣繳主體、折現政策或新的抽獎。其餘獎品品牌與型號沿用待公告狀態。

上述待公告事項仍須如實揭露，不因 `publicNoticeApproved` 設為 `true` 而宣稱定案。目前入口持續 CLOSED，正式入口網址仍空白、開始時間仍未定；須待帳號代辦私下說明的時序確認、同步最終公告並完成正式開放驗收後更新。發布新版公告或完成測試環境驗收，都不等於開放正式收件。

## 2026-10-12 授權公告修訂

`src/lib/consent.ts` 是公告、四項同意、聯絡方式與適用場館的文字正本；App 與登記入口均引用同一份常數。獨立的 Apps Script 專案須鏡像同版本、全文及完整告知，並以契約測試比對，不能只更新摘要。

- 首波抽獎須在期限內完成填表、四項主動同意並成功送出；中籤後的場地登記程序是另一件事。
- 維持 13 個固定場館，無逐館選項；不再將先前年度營運公司或登記系統寫成已驗證的 2027 年資訊。各館分列營運／受理單位判定方式與申請流程依據。
- 新增場館採人工補充授權：Email 文件或連結、LINE 社群公告、管理人員經報名系統私訊提供文件；本人明確同意後才納入。人工核對與留存回覆，不假稱已建置自動核身或補充授權系統。
- 即使營運單位承接其他場館、帳號可跨館使用，也不擴張原授權範圍。
- 帳號以本人名義申請，僅在營運單位允許的範圍共同操作；本人自行完成必要驗證、繳費、簽約及切結，沒有代簽或金錢承諾授權。
- 終止授權入口為曜日報名系統官方帳號與阿定 `nplus168`。人工核對、停止未執行代辦及後續使用、留存紀錄並回覆，不承諾自動刪除第三方會員或取消既有租約。
- 原有同意紀錄與版本不得回寫成新版；原授權不因此自動增加共用帳號或新增場館的範圍。
- 公開內容不包含登入資訊設定公式；表單不收集帳號密碼或一次性驗證碼。帳號設定與共用方式須在取得該項同意前，以非公開方式向本人說明。

本次未建置登入資訊保管、自動補充授權或第三方帳號停權功能，亦未逐館查核代辦／共用帳號條款。這不表示第三方已允許或安全措施已完成。資料利用地區依 Google、LINE 與 GitHub 公開政策說明，告知附有政策來源；本活動未指定單一資料儲存國家，不宣稱所有資料僅在臺灣處理，也不表示每筆資料均傳輸至政策列出的所有地區。這份文件描述實作範圍，不構成法律合規認證。

## 完整文件閱讀流程（v14）

Google 託管表單採兩階段：先填資料並通過格式檢查，再閱讀完整文件。文件包含全部 10 項個資與授權告知、13 個適用場館及活動辦法，須捲動至文件底部才能確認四項同意及送出。捲動位置只控制操作流程，不能證明本人已閱讀或理解，也不自動代替主動同意。

GitHub 頁面只解釋流程與預覽全文，不收集個資、不把頁面捲動轉成報名紀錄。正式版本、閱讀聲明、四項同意與完整文件內容，由 Google 託管表單後端檢查並依其紀錄規格保存；上線須以雲端實際送件與 Sheet 讀回驗收，不能只靠本機測試。

### 雲端驗收紀錄與尚待確認事項

2026 年 10 月 12 日已於 Google 測試環境驗證完整告知的閱讀閘門及實際送件流程，並成功讀回 Sheet 全部 22 個欄位。驗收同時修正多行活動規則的傳遞，以及 Google Sheet 將勾選值以文字讀回時的核對方式。測試結果證明該測試版本可正常處理此流程，不代表正式收件已開啟。

尚待確認帳號設定與共同使用的私下說明時序：是否在實際代辦或共同操作前，以私訊說明並另行確認。目前仍沿用尚未開放的告知版本，不將待確認的人工流程寫成已經完成。確認後須同步網站、Google 表單、完整告知快照與版本，再進行正式開放驗收；在此之前，前端收件設定保持關閉。

## 本機使用

需求：Node.js 22.13 或更新版本、npm。

```sh
npm ci
npm test
npm run dev
```

建立正式靜態檔：

```sh
npm run build
npm run preview
```

部署檔位於 `dist/`，網站基底路徑是 `/solar-court-project/`。變更儲存庫名稱時，也必須同步調整基底路徑、canonical 與分享預覽網址。

## 自動部署

在 GitHub 儲存庫的 Settings → Pages 將 Source 設為 GitHub Actions。推送至 `main` 或手動執行 `Deploy GitHub Pages` 工作流程後，會安裝鎖定的依賴、建置、上傳靜態檔並部署。

請以成功的 GitHub Actions 工作流程、Pages 部署狀態與實際網站讀回確認發布完成，不要只以本機建置成功判定。

## 資料與安全

- 不要上傳 `.env`、API 密鑰、登入憑證、參加者名單、Google Sheets 匯出檔或測試個資。
- 本儲存庫不包含 Apps Script 程式、試算表識別碼或 Sites 的伺服器設定。
- Google 託管表單與私有名單由獨立的 Apps Script 專案管理；本儲存庫不會直接呼叫收件 API，也不使用 `no-cors` 假設送出成功。
- `src/lib/registration-validation.ts` 與其合成測試保留作後端驗證的對照規格，目前 GitHub 頁面不接受或驗證使用者個資。
- 開放前完成伺服器端驗證、濫用防護、去重、回條與保存規則，再使用隔離測試名單驗收；不得把測試個資寫進正式名單。
- 既有 Sites 網站與 Google Sheets 不會因這個靜態版本而被變更。
