設定集中在 `src/lib/registration-config.ts`。v16 正式 Google 部署第 8 版已開放並通過端到端驗收，前端設定恢復為 `open: true`。保留既有 `formUrlVerified: true`、`publicNoticeApproved: true`、開始時間 `2026-10-12T23:07:34+08:00` 及[正式入口網址](https://script.google.com/macros/s/AKfycbwtRZZ7RtPE2Qz1FU_p7Qumj-9M7nyiK-LCySVVvoCevTiV_y3JqO6peOaPEVJbX3J_/exec)。GitHub Pages 的本次推送、部署與入口讀回均已完成確認，驗收紀錄見下方 v16 正式版章節；Google 收件驗收與 GitHub Pages 發布驗收分別執行。

`publicNoticeApproved` 只代表目前公開告知版本獲核可，不表示仍待公告的獎品價值或稅務細節已確定。開始時間必須含時區，前端與 Google 後端需一致。場地協助登記截止為 2027 年 12 月 31 日 23:59:59（台北時間），自 2028 年 1 月 1 日 00:00:00 起停止導向登記；此期限不是首波抽獎資格截止。

- 所有開放條件必須同時成立；單改 `open` 不會產生可用連結。
- 網址只接受 `https://script.google.com/macros/s/<deploymentId>/exec`；不接受 query、hash、帳密、其他網域或 `/dev`，不能放參加者個資或共用密鑰。
- URL 格式檢查不等於部署驗收；更換網址後必須重新驗收並更新 `formUrlVerified`。
- 開放前同步檢查 `index.html` 的 title、description、OG、Twitter 與 noscript 文字，以及 Google 表單的實際開始／截止設定與完整活動辦法。
- 本版告知版本為 `2027-v16-2026-10-13`，須與 Google 託管表單、後端保存的同意快照一致；不得改寫既有 v15 紀錄。
- GitHub 頁面的時間檢查只是入口提示；Google 表單後端必須獨立依伺服器時間、收件開關與完整驗證拒收未開放或逾期資料。

## 2026-10-12 授權公告修訂（v15 歷史）

`src/lib/consent.ts` 是公告、四項同意、聯絡方式與適用場館的文字正本；App 與登記入口均引用同一份常數。獨立的 Apps Script 專案須鏡像同版本、全文及完整告知，並以契約測試比對，不能只更新摘要。

- 首波抽獎須在期限內完成填表、四項主動同意並成功送出；中籤後的場地登記程序是另一件事。
- 維持 13 個固定場館，無逐館選項；不再將先前年度營運公司或登記系統寫成已驗證的 2027 年資訊。各館分列營運／受理單位判定方式與申請流程依據。
- 新增場館採人工補充授權：Email 文件或連結、LINE 社群公告、管理人員經報名系統私訊提供文件；本人明確同意後才納入。人工核對與留存回覆，不假稱已建置自動核身或補充授權系統。
- 即使營運單位承接其他場館、帳號可跨館使用，也不擴張原授權範圍。
- 帳號以本人名義申請，僅在營運單位允許的範圍共同操作；本人自行完成必要驗證、繳費、簽約及切結，沒有代簽或金錢承諾授權。
- 終止授權入口為曜日報名系統官方帳號與阿定 `nplus168`。人工核對、停止未執行代辦及後續使用、留存紀錄並回覆，不承諾自動刪除第三方會員或取消既有租約。
- 原有同意紀錄與版本不得回寫成新版；原授權不因此自動增加共用帳號或新增場館的範圍。
- 公開內容不包含登入資訊設定公式；表單不收集帳號密碼或一次性驗證碼。v15 允許先完成登記，但實際代辦或共同操作前，必須先以私訊說明帳號設定方式及操作範圍，取得本人另行明確確認且營運單位允許後才執行。未確認不得建立或共同操作帳號；登記本身不代表已收到私下說明或作出後續確認。

本次未建置登入資訊保管、自動補充授權或第三方帳號停權功能，亦未逐館查核代辦／共用帳號條款。這不表示第三方已允許或安全措施已完成。資料利用地區依 Google、LINE 與 GitHub 公開政策說明，告知附有政策來源；本活動未指定單一資料儲存國家，不宣稱所有資料僅在臺灣處理，也不表示每筆資料均傳輸至政策列出的所有地區。這份文件描述實作範圍，不構成法律合規認證。

## 本機使用

需求：Node.js 22.13 或更新版本、npm。

```sh
npm ci
npm test
npm run dev
```

建立正式靜態檔：

```sh
npm run build
npm run preview
```

部署檔位於 `dist/`，網站基底路徑是 `/solar-court-project/`。變更儲存庫名稱時，也必須同步調整基底路徑、canonical 與分享預覽網址。

## 自動部署

在 GitHub 儲存庫的 Settings → Pages 將 Source 設為 GitHub Actions。推送至 `main` 或手動執行 `Deploy GitHub Pages` 工作流程後，會安裝鎖定的依賴、建置、上傳靜態檔並部署。

請以成功的 GitHub Actions 工作流程、Pages 部署狀態與實際網站讀回確認發布完成，不要只以本機建置成功判定。

## 資料與安全

- 不要上傳 `.env`、API 密鑰、登入憑證、參加者名單、Google Sheets 匯出檔或測試個資。
- 本儲存庫不包含 Apps Script 程式、試算表識別碼或 Sites 的伺服器設定。
- Google 託管表單與私有名單由獨立的 Apps Script 專案管理；本儲存庫不會直接呼叫收件 API，也不使用 `no-cors` 假設送出成功。
- `src/lib/registration-validation.ts` 與其合成測試保留作後端驗證的對照規格，目前 GitHub 頁面不接受或驗證使用者個資。
- 開放前完成伺服器端驗證、濫用防護、去重、回條與保存規則，再使用隔離測試名單驗收；不得把測試個資寫進正式名單。
- 既有 Sites 網站與 Google Sheets 不會因這個靜態版本而被變更。

`public/marketing/` 的三張概念插畫分別用於首屏、資料登記及場地協助；目前引用 `community-illustration-v2.webp`、`registration-illustration-v2.webp` 與 `court-support-illustration-v2.webp`，以虛構成年男性球友呈現斯文與肉壯大叔等不同形象。均標示「AI 概念插畫，非實際球友或場地」，不作為實際成員或場館的紀錄。圖片設定寬高並使用網站基底路徑，首屏以外延遲載入；關鍵條件、日期與獎金保留為 HTML 文字，沒有燒進圖片。素材提示詞與用途見 `docs/marketing-assets.md`。
